# Auto Labeling with an LLM：用 Qwen2.5-0.5B 为 ChnSentiCorp 自动标注情感

## 1. 数据集与任务

- **数据集**：[ChnSentiCorp](https://huggingface.co/datasets/lansinuote/ChnSentiCorp)（中文情感公开数据集，酒店/图书/电脑评论），取其**测试集**（1,200 条，正 608 / 负 592，随代码附 `chnsenticorp_test.parquet`）。
- **输入特征**：中文评论文本。
- **标注目标**：情感二分类，标签集 {正面, 负面}。数据集自带人工标注（gold），用于评估模型标注质量。

## 2. 模型与方法

- **模型**：`Qwen/Qwen2.5-0.5B-Instruct`（0.5B 参数指令模型）。
- **调用方式**：**本地 CPU 推理**（transformers 4.57 + torch 2.8 CPU，无 GPU、无 API Key，单机可复现）；代码同时兼容换成任意 OpenAI 协议 API（见 `LocalLLM` 类的替换点）。
- **提示词设计**（约束式输出，关键三点）：
  1. system 固定角色「严谨的数据标注员」；
  2. user 中**白名单标签集**（只允许 正面/负面）+ **只输出 JSON** `{"label": "..."}`，禁止多余文字；
  3. 解析失败时把模型原输出回填进对话，**追加纠错指令重试一次**。
- **抽样与解码**：分层抽样 60 条（正负各 30，seed=42 可复现）；贪心解码（do_sample=False）保证标注确定性；生成上限 16 token。

```text
system: 你是一名严谨的数据标注员，负责判断中文评论的情感倾向。
user:   请判断下面这条评论的情感倾向。
        只允许输出以下标签之一：正面、负面。
        只输出一个 JSON 对象，格式：{"label": "正面"} 或 {"label": "负面"}，不要输出任何其他内容。
        评论：{text}
```

## 3. 代码与运行

核心代码 `demo_code.py`（约 200 行）：读 parquet → 分层抽样 → 构造 prompt → 本地推理 →
JSON 鲁棒解析（正则提取 + 别名归一 + 重试）→ 写 `results.csv`（text/gold/model/raw/correct/延迟）→
终端输出准确率与混淆统计。

```bash
pip install torch transformers pandas pyarrow
python demo_code.py --n 60          # 首次运行自动下载约 1GB 权重
```

**实测结果（本机 CPU，60 条，3.0 分钟）**：

| 指标 | 数值 |
|---|---|
| 标注成功率（输出合法 JSON 且落入标签集） | **60/60 = 100%** |
| 与人工标注一致率（准确率） | **51/60 = 85.0%** |
| 正面召回 / 负面召回 | 25/30 (83%) / 26/30 (87%) |
| 单条延迟（中位 / 最快 / 最慢） | 2.8s / 1.8s / 4.9s |

示例（results.csv 摘录）：

| 评论（截断） | 人工 | 模型 |
|---|---|---|
| 房间细小、地毡恐布，空调不够、服务差劣… | 负面 | 负面 ✓ |
| 虽然我住的是豪华房，但是房间的设施还是显得有些陈旧… | 正面 | 负面 ✗ |
| 这书也能推荐？重点几乎都在为自己说好话… | 负面 | 正面 ✗ |

## 4. 结果分析

- **模型强项**：语义清晰的单调评论几乎全对；对约束输出格式服从性极好（JSON 合法率 100%，
  0 条解析失败），说明"白名单标签 + JSON-only + 失败重试"的提示词结构对 0.5B 小模型也够用。
- **9 条错误的模式**（逐条人工归因）：
  1. **混合情感（4 条）**：整体褒但夹带明显抱怨（"虽然豪华房，但设施陈旧…"），模型抓住局部
     负面词判负；gold 按整体倾向标正。这是最大错误来源。
  2. **反讽/修辞（1 条）**："这书也能推荐？"——反问句式，0.5B 模型读不出讽刺。
  3. **gold 噪声/歧义（2 条）**："还没有发现什么不足×4" 被人工标为负面，但字面明显无抱怨，
     模型判正面未必错——公开数据集本身有标签噪声（ChnSentiCorp 已知有少量噪声）。
  4. **平铺直叙的抱怨（2 条）**：以客观口吻罗列缺点（"散热口温度蛮高…没附系统盘…"），
     无强负面情感词，模型被"还行/可以"等弱正面词带偏。
- **何时好、何时坏**：情感词与整体倾向一致时近乎全对；**好坏混杂、反讽、依赖领域常识**
  （如"待机时间长"是优点）时容易错——即失败集中在"需要整体语篇理解而非词面匹配"的样本。

## 5. 人工标注 vs 模型自动标注

| 维度 | 人工标注 | LLM 自动标注（本 demo） |
|---|---|---|
| 速度 | 60 条约 30–60 分钟 | 3 分钟（CPU）；GPU/API 下秒级 |
| 成本 | 人力成本高、难扩量 | 电费级；API 约 $0.01–0.05/千条（小模型） |
| 一致性 | 同一人前后期、多人之间都会漂移，需标注规范+仲裁 | 贪心解码完全确定，同输入必同输出 |
| 语义理解 | 强：反讽、语境、领域常识可靠 | 反讽与混合情感仍是弱项（本实验 15% 错误） |
| 偏差 | 主观疲劳偏差、个人立场偏差 | 训练数据偏见（如倾向字面情感词）；错误是**系统性**的，可归因可迭代 |
| 适用 | 高价值终版标注、争议仲裁 | 冷启动、粗标+人工复核、大规模弱监督 |

结论：两者互补——LLM 做**初标**（快、便宜、一致），人工做**抽检与仲裁**，是性价比最高的组合。

## 6. 改进想法

1. **自一致性投票（Self-Consistency）**：同一文本采样 k=5 次取多数票，配合多次输出的一致率
   作为置信度；一致率低的样本自动进入人工复核队列（置信过滤 + human-in-the-loop）。
2. **结构化两步标注**：先让模型抽取评论中每个观点子句及其倾向（aspect-level），再按"整体
   倾向 = 主导观点"聚合。针对本实验最大错误源（混合情感）直接对症。
3. **少样本提示（few-shot）**：在提示词中加入 2–3 个带噪声场景的示例（反讽、混合情感），
   通常可再提升 3–5 个点，代价是每次请求变长。
4. **升级模型**：换 1.5B/7B 或 API 模型验证规模效应；用本方案批量标注 5–10 万条后微调
   一个小分类器（蒸馏），推理成本可降两个数量级。
